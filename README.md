# Drive Workspaces

Edge のワークスペースのように「ウィンドウ単位のタブ状態」を、Google Drive 経由で
デバイス間・ブラウザ間（Chrome / Edge などの Chromium 系）で同期する、自分用の拡張機能です。

- 保存先: 拡張機能でサインインしたGoogleアカウントのGoogle Drive の **appDataFolder**（Drive の画面に出ない拡張専用の隠しフォルダ）
- スコープ: `drive.appdata` のみ（Google の区分で「非機密」）
- 費用: 無料（Google Cloud プロジェクト・Drive API とも無料枠内）

## できること / できないこと

| できる | できない |
|---|---|
| ウィンドウをワークスペースとして保存し、別端末・別ブラウザで同じ状態で開く | 即時反映（同期は最短約30秒ごと＋ウィンドウにフォーカスしたとき） |
| タブの URL・順序・ピン留め・タブグループ（名前・色・折りたたみ）の同期 | 戻る/進む履歴、スクロール位置、フォーム入力、ログイン状態の再現 |
| 開いているウィンドウへの差分適用（URL が同じタブは再利用） | `chrome://` `edge://` などブラウザ固有ページの同期（ローカルには残る） |
| ブラウザ再起動や「ページを復元」のあと、目印タブでウィンドウとワークスペースを自動で結び付け直す | 同じワークスペースを2台で同時編集したときのマージ（両方が変わったら、どちらを残すか確認する） |

アクティブなタブの切り替えは同期しません（切り替えるたびに他端末のウィンドウが動くのを防ぐため。開くときだけ復元します）。

## セットアップ

### 1. ビルド

```bash
npm install
npm run keygen   # 拡張IDを固定する鍵を生成。表示される拡張IDとリダイレクトURIを控える
npm run build    # dist/ が生成される
```

`extension-key.json` は公開鍵だけなので Git にコミットして構いません。**作り直すと拡張IDが変わり、
下の手順4のリダイレクトURIも登録し直しになります。**

### 2. Google Cloud プロジェクト

1. [Google Cloud Console](https://console.cloud.google.com/) でプロジェクトを作成
2. 「API とサービス」→「ライブラリ」で **Google Drive API** を有効化

### 3. OAuth 同意画面（Google Auth Platform）

1. ユーザーの種類: **外部**
2. アプリ名・サポートメールを入力
3. データアクセス（スコープ）に `https://www.googleapis.com/auth/drive.appdata` を追加
4. **公開ステータスを「本番環境」にする** ← 重要
   - 「テスト」のままだとリフレッシュトークンが **7日で失効** し、毎週サインインし直しになります
   - `drive.appdata` は非機密スコープなので、本番にしても重い審査は不要です
   - 未確認アプリのため、サインイン時に「Google はこのアプリを確認していません」と出ます。
     自分のアプリなので「詳細」→「（安全ではないページ）に移動」で進めます

### 4. OAuth クライアント

1. 「認証情報」→「OAuth クライアント ID を作成」
2. アプリケーションの種類: **ウェブアプリケーション**
   （「Chrome 拡張機能」型は `getAuthToken` 専用で、Edge などでは使えないため）
3. 承認済みのリダイレクト URI に、手順1で表示された `https://<拡張ID>.chromiumapp.org/` を追加
4. クライアント ID とクライアントシークレットを控える

### 5. ブラウザに読み込む（使う端末・ブラウザごとに）

1. `chrome://extensions`（Edge は `edge://extensions`）を開き、デベロッパーモードを ON
2. 「パッケージ化されていない拡張機能を読み込む」→ `dist/` を選択
3. 拡張IDが手順1と同じになっていることを確認
4. 拡張の「オプション」を開き、クライアントID・シークレット・端末名を入力 → **サインイン**

別の端末では `dist/` をコピーして同じ手順5を行います（鍵が同じなので拡張IDも同じになります）。

## 使い方

- ツールバーのアイコン → 名前を入れて「保存」で、今のウィンドウがワークスペースになります
- 一覧をクリックで開く（既に開いていればそのウィンドウに移動）
- 一覧の並び順は「最近使った順」「名前順」を切り替えられます（プロファイルごとに記憶）。
  「最近使った」はタブを変更したときと、ワークスペースを開いたときに更新されます
- 一覧の「最終:」に、最後に使った端末・ブラウザ・プロファイル（例: `自宅PC / Edge / ittama`）が表示されます。
  ブラウザは自動判定です（Vivaldi など判定できないものは `Chromium`。設定画面で手入力できます）。
  プロファイル名は拡張機能から取得できないため、プロファイルごとに設定画面で入力してください
- 最後に別のブラウザ・プロファイルで使われていたワークスペースを開くときは、確認ダイアログが出ます
- ワークスペースのウィンドウの先頭には、ワークスペース名の折りたたみタブグループが付きます。中身は目印のタブ（google.com）で、
  ピン留めタブがあるウィンドウではその直後に置かれます。閉じたり別のページへ移動したりしても自動で作り直され、
  普通のウィンドウに戻すときは ⋯メニューの「関連付け解除」を使います
- 目印が付いていないウィンドウは、⋯メニューの「このウィンドウに結び付ける」でワークスペースに結び付けられます
- 「閉じる」で保存してからウィンドウを閉じます。ウィンドウを普通に閉じても状態は保存済みです
- ×でウィンドウを閉じると、ブラウザの保存済みタブグループに記録が残ることがあります（ブラウザの機能で、拡張機能からは消せません）。
  ⋯メニューの「閉じる」なら残りません
- 「削除」は全端末から消えます（開いているウィンドウ自体は閉じません）
- バッジに `!` が出たら、同期エラーか内容の確認待ちです。ポップアップに内容が表示されます
- 手元と Drive の両方が変わっていると、自動では上書きせず、ポップアップでどちらを残すか確認します。
  両方残したいときは、関連付けを解除してから新しいワークスペースとして保存してください

## 仕組み

```
src/
  background.ts  サービスワーカー。タブ/グループのイベント監視、30秒アラーム、メッセージ処理
  sync.ts        同期の中核（アップロード・差分取り込み・競合判定・目印との突き合わせ）
  anchor.ts      目印タブの URL の生成と判定（純関数）
  anchorTab.ts   目印タブとタブグループの操作
  conflict.ts    手元の変更と Drive の新旧の判定（純関数）
  outbox.ts      送信待ちキューの判定ロジックとデバウンス（純関数）
  alias.ts       反映で作ったタブの「要求した URL」の別名の判定（純関数）
  snapshot.ts    ウィンドウ状態の取得と差分適用
  drive.ts       Drive API v3（appDataFolder の CRUD と changes.list）
  auth.ts        launchWebAuthFlow + 認可コード + PKCE、リフレッシュトークン管理
  store.ts       chrome.storage のラッパー
  popup.* / options.*  UI
  test/          純関数の単体テスト（npm test。Node 標準の node --test を使用）
```

- **テスト**: `npm test` で `hashOf`・`isSyncable`・`isWorkspaceDoc` などの純関数の単体テストが走ります（node:test などの標準機能のみで、テストランナーの追加依存はありません）
- **保存形式**: ワークスペース1つにつき `ws-<uuid>.json` 1ファイル。別々のワークスペースを別端末で同時に触っても衝突しません
- **ローカル → Drive**: タブの変更時にすぐウィンドウの状態を撮影し、送信待ちキュー（`chrome.storage.local` の outbox。ワークスペースごとに最新状態1件）に積む。送信は0.5秒デバウンス（操作が続いても最大2秒）で、失敗したものはキューに残り30秒アラームで再送。撮影済みなので、×ボタンで閉じた直後やブラウザ再起動後でも最後の状態が送られる（ただし操作から数十ms以内に閉じた場合、撮影中に閉じ始めた状態は途中経過の恐れがあるため捨てる）。リモート適用中の操作は、適用ガードの解除後に撮り直す
- **Drive → ローカル**: `changes.list`（`spaces=appDataFolder`）を30秒ごと＋フォーカス時（3秒間隔まで）にポーリング。フォーカス時は送信も先に行う。未送信の変更があるワークスペースはリモートでタブを上書きしない
- **ウィンドウの結び付け**: windowId はブラウザ再起動で変わり、ウィンドウ自体に名前などを付ける API もないため、先頭の目印タブ（`https://www.google.com/#dw=<ワークスペース ID>`）で見分ける。`#` 以降はサーバーへ送られず、ワークスペース名も URL に入れない。タブはセッション復元で URL ごと戻るので、復元がいつ行われても、ウィンドウやタブのイベントと30秒アラームで結び付け直せる。先頭にない目印や重複した目印は無効として閉じる（保存済みタブグループを別のウィンドウで開いたときなどに、無関係なタブをワークスペースへ送らないため）。目印の作り直しは同じウィンドウで10分間に3回まで（URL がリダイレクトされる環境でタブが増え続けないように）
- **復元したウィンドウの新旧**: ウィンドウが最後に Drive と一致した内容のハッシュを端末ごとに記録する。閉じている間の Drive の更新では変わらないので、ウィンドウと Drive のどちらが変わったかを判定できる。Drive だけが新しければウィンドウへ反映し、ウィンドウだけが新しければ送信し、両方が変わっていれば確認する
- **競合**: 新旧は Drive の `modifiedTime`（サーバー時刻）で判定する。Drive v3 は ETag による条件付き更新を公開していないため、送信の直前にメタデータを確認する（確認と送信のごく短い隙間に書かれた更新は後勝ちになる）。手元の未送信と Drive の両方でタブが変わっていれば、送信も反映も止めて確認する。名前や時刻だけの更新は競合として扱わない
- **エコー防止**: タイトルとアクティブタブを除いた内容のハッシュで変化を判定。リモート適用中（＋解除まで1.5秒）は撮影せず、解除後に撮り直す（適用しただけなら同期済みと同じハッシュなので送信されない）
- **リダイレクト対策**: 他端末の状態を反映して作ったタブは、ユーザー自身が移動させるまで要求した URL で記録・照合する（未ログインでログイン画面に飛ばされた URL などを他端末に送り、元のタブを置き換えてしまわないため）。ユーザー自身の移動とみなすのは、一度読み込みが完了した後、アクティブなタブで、前回の URL 変化・読み込み完了から3秒以上たって URL が変わったとき。別名はブラウザ再起動後も、結び付けたウィンドウのタブへ付け直す。近似なので、読み込み直後3秒以内の自分での移動は次の移動まで反映されず、3秒より遅いスクリプトのリダイレクトは送信される
- **安全装置**: ウィンドウを閉じるときのタブ削除イベントは無視。空のタブ一覧は保存しない

## 注意

- **自分専用の前提です。** Google の「ウェブアプリケーション」型クライアントは PKCE を使っても
  トークン交換に client_secret を要求するため、シークレットを拡張内（`chrome.storage.local`）に保持しています。
  配布する場合はトークン交換をサーバー側に移す必要があります
- 動作確認しているのは型チェック、`npm test` の単体テスト、タブ差分適用ロジックのモックテストまでです。
  実ブラウザでの動作（特に Brave / Vivaldi / Opera の `launchWebAuthFlow`）は未検証です
- サイトのリダイレクト（http→https など）で URL が変わると、それが他端末にも反映されます（1回で収束します）
